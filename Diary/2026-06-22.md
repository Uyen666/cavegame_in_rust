# 2026-06-22 更新日記

## 1. 負座標座標截斷災難修復 (Negative Coordinate Truncation Fix)
修復了 `update_fog_color` 中使用 `.as_ivec3()` 導致的致命取樣錯誤。在 Rust / Bevy 中，浮點數直接強制轉型為整數是向零截斷 (Truncate towards zero)，這會導致在負座標區域時，陣列索引或區塊座標偏移 1 格，進而引發邊界存取錯誤。我們已經全面改用剛性的 `.floor() as i32` 幾何向下取整，確保跨越座標原點時的光照與區塊採樣維持絕對完美一致。

## 2. FixedUpdate 雙軌視角同步 (Jitter-Free Camera)
為了解決玩家移動時視角瘋狂抖動 (Jitter) 的問題，我們對系統排程進行了鐵血大搬風。原本相機旋轉 (`player_look`) 放在變動幀率的 `Update`，而物理移動 (`player_move`) 卻在固定的 `FixedUpdate` (128Hz)，這導致了嚴重的相位差撕裂。現在我們將兩者剛性綑綁在同一個 `FixedUpdate` 中執行，徹底消除了任何微觀錯位，達成了極致平滑、指哪打哪的跟手視角體驗。

## 3. 陸地連跳與輸入緩衝 (Bunny Hopping & Input Buffering)
為了還原 Minecraft 最經典、最順暢的連跳手感，我們在 `Player` 結構體中注入了全新的 `wants_to_jump` 動作鎖存器！
- **高頻捕獲**：在 `Update` 階段即時捕獲鍵盤輸入，保證再快的點擊都不會漏鍵 (Anti-Ghosting)。
- **無縫交集**：在 `FixedUpdate` 中，將鎖存器與「按住空白鍵」進行雙軌交集判定。這意味著你可以按住空白鍵無縫連續起跳 (Bunny Hopping)，也可以在落地前零點幾秒提前點擊，落地瞬間完美觸發起跳 (Input Buffering)。
- **鐵血消費**：一旦賦予跳躍衝量或是玩家懸空未按鍵，系統會無情洗淨鎖存器，徹底杜絕不受控的自動鬼跳。

## 4. 存檔系統：雙軌真空流體防線 (Dual-Vacuum Fluid Save Defense)
我們挖出了一個潛伏在 `storage.rs` 裡的恐怖資料流失 Bug：原本系統只檢查固體方塊是否為空氣 (`data.buffer.is_pure_air()`)，導致高空懸浮的水源或瀑布被當作廢棄區塊直接丟棄。
為了根絕流體蒸發，我們對底層資料實施了外科手術：
- 將 `ChunkData` 升級，加入了相容於 Serde 序列化的 `Option<Vec<u8>>` 流體緩衝區。
- 實作了極度嚴格的雙重防線：`let is_empty_chunk = data.buffer.is_pure_air() && data.is_fluid_pure_vacuum();`。
現在，即使一個區塊內 100% 全是空氣，只要還殘留「一滴水」，它就會被老老實實地序列化寫入硬碟中。從此深淵的瀑布再也不會因為重開機而無故枯竭！
