## 🔧 今日重構與修復：UI 物品欄 3D 體素網格渲染與繞行校準 (Unified UI Meshing & Winding Alignment)

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **現象**：在物品欄快捷列 (Hotbar) 中，草方塊 (Grass) 與橡木原木 (Oak Log) 等方塊預覽圖呈現右側穿透/缺面破洞，原木方塊右側可直接透視至內部底部的同心圓年輪，猶如一個空心盒子。
* **數學與圖形學根本原因**：
  * Bevy 的 `VoxelMaterial` 啟用了嚴格的硬體背面剔除（`Face::Back`，正面定義為逆時針 CCW）。
  * 舊版 `build_single_voxel_mesh` 採用手寫頂點表，其 `(0, false)`（+X 面）的頂點 Z 軸順序寫反，造成 $(v2 - v1) \times (v3 - v1) = (-1, 0, 0)$，三角形法線反向指向 $-X$（內部）。從 UI 攝影機視角 $(+X, +Y, +Z)$ 觀察時，該面被判定為順時針背面而遭 GPU 剛性剔除。
  * 同時，底面與背面手寫頂點表存在重複反轉，導致從內部觀察時為正面，因此穿透右側面後會清晰看見內部底面（`oak_log_top` 年輪貼圖）與背面。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **切線空間與索引繞行標準化 (`src/render/greedy.rs`)**：
  * 徹底淘汰低效且容易出錯的手寫頂點分支，全面改用與區塊貪婪網格生成器（Greedy Mesher）完全一致的切線空間基底向量 $(u, v)$ 與軸向位移公式：
    * $d=0$ (X 軸)：$u=Y, v=Z \implies du \times dv = +X$
    * $d=1$ (Y 軸)：$u=X, v=Z \implies du \times dv = -Y$，剛性套用 `rev = !rev` 維持 $+Y$ 朝外法線
    * $d=2$ (Z 軸)：$u=X, v=Y \implies du \times dv = +Z$
  * 確保所有 6 個面的三角形繞行法線嚴格、無條件朝外，徹底根治任何視角下的缺面破洞問題。

* **火把特化雙面渲染 (`push_single_torch_mesh`)**：
  * 將火把的 3D 預覽網格生成抽離至專屬函數，對 6 個面均推入正面（`rev = false`）與背面（`rev = true`）雙面幾何（共 12 Quad / 48 頂點），使微型長條幾何在 UI 槽位中 360 度無死角顯色。

## 🔧 今日重構與修復：火把破壞光源殘留根治、四階段正交光照更新與 UI 網格記憶體優化

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **火把破壞後光源永久殘留**：
  * 舊版 `set_block_global` 採用了 `if block == BlockType::Air { ... } else { ... }` 粗暴二分。
  * 當玩家打掉火把（將火把置換為 `Air`）時，系統錯誤進入挖開實心泥土的邏輯分支，不僅未呼叫 `remove_block_light_global`，反而直接讀取火把自身殘留的周遭方塊光 (13~14 級) 並執行 `propagate_block_light_global`，將自身的光再次廣播蔓延，導致火把光源永遠無法消退。
  * 阻斷光照消除邏輯 `remove_block_light_global` 原先被深埋在 `else`（放置方塊）分支中，任何將方塊置換為 `Air` 的操作都無法觸發發光方塊的光照消除。
* **快捷列 UI 每幀記憶體洩漏與重複生成**：
  * `update_hotbar_ui` 原先查詢 `Changed<Player>`。由於滑鼠旋轉相機視角每影格都會修改 `Player` 組件，導致 UI 系統每一影格都在無條件執行。
  * 每一槽位未記錄當前方塊類型，無條件調用 `meshes.add(...)` 生成 9 個全新的 Bevy `Mesh` 資產，導致內存快速膨脹與 GPU 資源浪費。
* **玻璃方塊破壞掉落與光照阻斷問題**：
  * 原先玻璃 (`Glass`) 在 `BlockDefinition` 中定義為 `DropTable::None`，但在 `get_block_drop` 中回傳預設的 `ItemType::from_block(other)`，導致打碎玻璃依然掉落玻璃。
  * 天空光與方塊光 BFS 蔓延在判定阻斷時，硬編碼比對 `BlockType::Air`，導致穿過玻璃或火把時天空光被錯誤阻斷。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **四階段正交光照更新管線 (`src/world/mod.rs`)**：
  * 重構 `set_block_global` 為四大互不干擾的正交物理階段：
    1. **5a. 舊光源銷毀消除**：若 `old_block.light_emission() > 0 && old_block.light_emission() > block.light_emission()`，先將當前座標歸零，並向外廣播 `remove_block_light_global` 與相鄰光源重新氾濫 (Re-flood) 佇列。
    2. **5b. 新不透明方塊遮蔽**：若 `block.is_opaque()`，消除該處殘留的天空光與方塊光。
    3. **5c. 挖開固體外界光線湧入**：若 `old_block.is_opaque() && !block.is_opaque()`，引導頂部陽光或周圍光線湧入。
    4. **5d. 新光源放置擴散**：若 `block.light_emission() > 0`，廣播新方塊光。
  * 在 `lighting.rs` 中，將光照透光檢測統一為 `!block.is_opaque()`，確保光線自然穿透玻璃、樹葉與火把。
* **UI 網格緩存與查詢解耦 (`src/ui/hud.rs`)**：
  * 將 UI 系統查詢改為 `Changed<Inventory>`，徹底杜絕滑鼠轉向時每影格觸發。
  * 在 `UiPreviewMesh` 組件中追加 `current_block: BlockType` 欄位進行狀態快取，僅在槽位物品類型實質變更時調用 `meshes.add`，根治記憶體洩漏。
* **掉落表嚴格對齊 (`src/item/mod.rs`)**：
  * `get_block_drop` 優先檢查 `block.drop_table() == DropTable::None` 並直接回傳 `None`，使玻璃等特殊方塊破壞行為符合物理設計。

## 🔧 今日重構與修復：夜晚水體過亮缺陷根治與流體雙軌光照頂點平滑採樣

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **現象**：在夜晚或黃昏時，地表方塊（草地、樹木、泥土）隨環境光照平滑變暗，但水面（河流/瀑布）依然保持白天般刺眼高亮的電藍色，如同自身帶有 15 級強光源。
* **圖形學與位元打包根本原因**：
  * 在 `src/render/greedy.rs` 的 `push_fluid_quad` 函數中，頂點光照計算僅向鄰近採集了天空光 `world.get_light_global(sample_gp).0`。
  * 在將光照位元寫入頂點打包資料 `packed_data: u32` 時，舊代碼出現了嚴重偏差：
    ```rust
    // 舊代碼：錯誤地將 smooth_light 同時寫入 bits 24..28 (方塊光) 與 bits 28..32 (天空光)
    | (((smooth_light as u32) & 0x0F) << 24)
    | (((smooth_light as u32) & 0x0F) << 28)
    ```
  * 在著色器 `voxel.wgsl` 中，頂點與片元著色器依照位元解包：
    `let block_light_int = (input.packed_data >> 24u) & 0x0Fu;`
    `let sky_light_int = (input.packed_data >> 28u) & 0x0Fu;`
    `let final_light = max(in.sky_light * env.sky_factor, in.block_light);`
  * 由於 `in.block_light` 被強行塞入地表天空光（15 級），即使夜晚 `env.sky_factor` 下降至 `0.05`，`final_light` 依然被 `max(0.75, 15.0) = 15.0` 剛性截斷在 100% 滿亮！陰影係數 `shadow_intensity` 恆定為 1.0，導致水體夜間宛如發光塑料。
  * 同時，舊代碼完全沒有採樣 `.1`（方塊光），導致在沒有天空光的地底洞穴中，水體永遠無法被火把照亮。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **流體雙軌光照平滑採樣 (`src/render/greedy.rs`)**：
  * 將 `push_fluid_quad` 的採樣邏輯重構為獨立雙軌：
    ```rust
    let mut sky_light_sum = 0;
    let mut block_light_sum = 0;
    for dx in dx_min..=dx_max {
        for dy in dy_min..=dy_max {
            for dz in dz_min..=dz_max {
                let sample_gp = base_gp + IVec3::new(vx + dx, vy + dy, vz + dz);
                let (sl, bl) = world.get_light_global(sample_gp);
                sky_light_sum += sl as u32;
                block_light_sum += bl as u32;
            }
        }
    }
    let smooth_sky_light = (sky_light_sum / 4).min(15) as u8;
    let smooth_block_light = (block_light_sum / 4).min(15) as u8;

    let packed: u32 = ...
        | (((smooth_block_light as u32) & 0x0F) << 24)
        | (((smooth_sky_light as u32) & 0x0F) << 28);
    ```
  * 精確對齊固體網格的位元規格：`[24..28]` 僅存放周遭真實火把方塊光，`[28..32]` 僅存放天空光。
  * 夜間時，地表水體 `smooth_block_light == 0`，`final_light` 順利降為 `15 * 0.05 = 0.75`，光照係數縮減 12 倍，水體與周遭暗夜環境完美融為一體；若在水旁插上火把，水面頂點則能自然接收火把方塊光（14 級），呈現溫暖的夜間倒影照明。

## 🔧 今日重構與修復：水中跳躍與流體移動物理工業級重構

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **水面「彈簧床連續拋射」破綻**：
  * 舊代碼在 `is_surface_escape` 判定下，只要露頭且按住 Space，在 128Hz 的 FixedUpdate 每一影格都重複賦值 `vel.y = config.physics.land_jump_impulse (8.5 m/s)`，導致連續十數影格不斷注入跳躍動能，玩家一接觸水面就如同踩在彈簧床上被猛烈彈起 1.5 米高，無法在水面上靜止踩水觀察。
* **水下「貼牆火箭電梯」失真**：
  * 舊代碼 `is_fluid_climbing` 僅依賴 `rb.is_colliding_horizontally`。只要在深海底部接觸任何垂直石壁並按 Space，每影格便以 8.5 m/s 強制垂直拔高，幾秒內即可無視水流阻尼衝上海面。
* **水底起跳水阻瞬時蒸發**：
  * 舊代碼在 `is_ground_jumping` 觸發時直接繞過水阻邏輯，水平速度瞬間切換為陸地模式，喪失流體慣性。
* **下潛鍵與疾跑鍵語義衝突**：
  * 陸地以 `ShiftLeft` 疾跑、`ControlLeft` 下蹲；但水中卻把 `ShiftLeft` 判定為下潛。若玩家在水中試圖疾跑游泳，反而會垂直迅速沉底。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **分層狀態機與平穩踩水 (`src/player/mod.rs`)**：
  * **水面踩水 (Surface Treading)**：開闊水面露出頭部時長按 Space，以 `(vel.y + 12.0 * dt).min(1.0)` 給予平緩浮力，剛性限速在 `vel.y <= 1.0 m/s`。使玩家眼球自然穩定在水線上方觀察四周，彻底根治彈簧床拋射現象。
  * **岸邊登岸翻越 (Ledge Vault / Shore Hop)**：當玩家頭部露於水面、正前方發生水平方塊碰撞 (`rb.is_colliding_horizontally`) 且輸入向前推進時，按下 Space 觸發翻岸衝量 (`vel.y = land_jump_impulse * 0.75 ≈ 6.38 m/s`)；並引入 `vel.y < 2.0` 單次觸發閘門，確保單次起跳僅給予單一拋物線，精準翻越 1 格高的河岸。
  * **穩態瀑布攀爬 (Controlled Fluid Climbing)**：水下完全浸入且貼壁按 Space 時，將上升速度限制為穩態攀爬 `vel.y = (vel.y + 20.0 * dt).min(3.0)`，還原真實逆流而上的游泳體驗。
  * **鍵位語義統一與水下疾跑**：水中下潛統一由下蹲鍵 `ControlLeft`（及 `KeyC`）控制；`ShiftLeft` 釋放為游泳疾跑，可提高水下游速（0.65x 速度比）。
  * **水底起跳阻力保留**：在河床上起跳時賦予 `0.85x` 衝量，水平方向持續保持流體慣性與阻尼。

## 🔧 今日重構與修復：第一梯隊 (Tier 1) 著色器距離迷霧、水流沖垮火把物理與透明方塊天光穿透

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **著色器端迷霧缺失導致加載邊界生硬切割**：
  * Bevy 0.14 自訂 `Material`（覆寫了 `fragment_shader()`）不會自動套用相機上的 `FogSettings`。
  * 導致遠處地平線上的地形在視距邊界突然斷崖式裁切，缺乏大氣透視感與遠景漸層。
* **水流遭遇火把如同撞上石牆（果凍阻斷）**：
  * 舊版 `fluid_tick_system` 與 `wake_up_fluids_in_radius` 嚴格限定 `neighbor_block == BlockType::Air` 才允許擴散。
  * 火把 (`BlockType::Torch`) 雖非固體 (`!is_solid()`)，但由於不是空氣，水流直接被火把像大壩一樣擋住，無法流入，亦無法將其沖刷熄滅。
* **天光穿透性阻斷**：
  * `init_sunlight` 與 `propagate_sky_light` 採用 `block == BlockType::Air` 判定透光，導致高空玻璃或透明方塊下方的空間被錯誤塗黑。

* **WGSL 片元著色器距離迷霧 (`assets/shaders/voxel.wgsl` & `src/render/material.rs`)**：
  * 在 `EnvironmentUniform` 中擴充 `fog_start: f32`, `fog_end: f32`, `fog_color: Vec4`, `camera_pos: Vec4`，嚴格遵守 16 位元組 std140 記憶體對齊。

  * 在 `fluid_tick_system` 中偵測水流擴散至 `block.is_torch()` 空間，自動呼叫 `set_block_global(pos, BlockType::Air, &mut commands)` 拆除火把。
  * 自動聯動光照消除管線（Phase 5a）將光源完全熄滅，並在玩家於拾取範圍內時自動返還火把至背包。
  * 在 `get_distance_to_drop` 與 `wake_up_fluids_in_radius` 中支援火把空間無阻礙探測與蔓延。
* **透明方塊天光穿透體系 (`src/world/lighting.rs`)**：
  * 全面將 `BlockType::Air` 判定替換為 `!block.is_opaque()`，確保陽光正確穿透玻璃、火把與透明結構。

## 🔧 今日重構與修復：第二梯隊 (Tier 2) 方塊採掘進度體系、36格全背包管理介面與採掘碎屑粒子

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **無硬度體系與點擊秒破壞**：
  * 原先點擊左鍵 `just_pressed(MouseButton::Left)` 會立刻以 1 幀速度將瞄準的任何方塊瞬間清空，忽視了各方塊的 `hardness` 與工具類型。
  * 玩家空手即可一瞬間粉碎堅硬岩石與礦石，缺乏核心生存採掘的累積反饋與工具升級的正向反饋。
* **缺乏破壞視覺粒子回饋**：
  * 方塊遭破壞或敲擊時直接消失，畫面顯得單調且缺乏物理打擊感。
* **僅有 9 格快捷列，缺乏全背包介面**：
  * 玩家只能在畫面下方的 9 格快捷列循環切換，超出 9 格的物品無法查看、整理或換位。

### 2. 工業級架構重構 (Production-Grade Architecture)
* **方塊採掘進度與硬度加權體系 (`src/player/mod.rs`)**：
  * 在 `Player` 組件中新增 `mining_target: Option<IVec3>` 與 `mining_progress: f32 (0.0..1.0)`。
  * 玩家長按左鍵持續瞄準方塊時累積採掘進度，進度累積速度嚴格遵循 Minecraft 工業標準公式：
    * 檢查手持工具是否符合方塊之 `preferred_tool()`（如鎬子之於岩石、斧頭之於原木、鏟子之於泥土）；
    * 檢查工具階級 `tier` 是否滿足 `required_tier()`；
    * 依據工具 `efficiency`（木: 2.0x, 石: 4.0x, 鐵: 6.0x）動態計算每秒破壞值；若空手或工具不匹配則大幅降速（5.0x 懲罰）；
    * 唯有滿足採集階級的工具採掘，方能獲得方塊掉落物；
    * 硬度為 0.0 之方塊（如火把）保留一擊即破的即時敲除體驗。
  * 採掘時瞄準線框動態漸層轉紅，並浮現內部破裂框，提供極佳的敲擊反饋。
* **輕量化 3D 體素碎屑粒子系統 (`src/render/particles.rs`)**：
  * 實裝 `ParticleManager` 資源，提供高效且無任何第三方庫依賴之 deterministic 快速隨機粒子發射引擎。
  * 敲擊過程中每 0.18 秒飛散 2 顆細微碎屑，方塊徹底破碎瞬間以方塊中心向 3D 空間爆發噴出 14 顆對應方塊材質代表色（草綠、岩灰、泥棕、木褐、沙黃、金屬色等）之體素立方體粒子。
  * 粒子具備初速度、重力加速度、地面彈性碰撞消解與平滑尺寸淡出，由 `Gizmos::cuboid` 一體化管線繪製，達成 0 Entity 生成開銷與 0 GC。
* **36 格全功能背包管理介面 (`src/ui/inventory.rs`)**：
  * 按下 `KeyE` 或 `Escape` 可平滑喚出/關閉居中半透明毛玻璃面板，並自動解鎖滑鼠游標。
  * 完整展示 36 格槽位（27 格主儲存區 + 9 格快捷列），支援縮寫名稱、堆疊數量與工具耐久度條顯示。
  * 支援完整游標拖曳置換/堆疊互動：左鍵點擊可拿起、放下、同類堆疊、不同物品交換；手持游標狀態即時顯示於標題列；關閉背包時手持物品自動無損歸還至背包。
  * 背包開啟期間剛性凍結玩家物理位移與相機轉向，防止操作衝突。

## 🔧 今日重構與修復：第三梯隊 (Tier 3) 3D DDA 快速體素遍歷演算法、區塊網格記憶體零拷貝提取優化與冗餘代碼清理

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **固定步長 (0.05m) 射線步進之累積穿透誤差與算力浪費**：
  * 原先在 `player_interaction`、`draw_target_block_highlight` 與 `update_crosshair` 中，均採用固定步長 (`step = 0.05`) 的線性循環步進。
  * 每次射線檢測需進行多達 100 次循環與全局座標查詢；在斜向視角穿透時容易在體素邊界交角發生「穿透漏檢」或命中錯誤方塊；
  * 方塊放置依靠 `last_air_pos` 記錄前一個步進點，在高速轉向或邊界處經常出現放置方塊錯位至隔壁或反向面的幽靈 Bug。
* **網格生成 (Greedy Mesher) 每幀 2.16MB 的巨額堆積堆疊分配**：
  * 舊代碼在 `mesh_dirty_chunks` 中為每個髒污區塊提取 3x3x3 (27個) 鄰居資料時，使用 `Box::new(entry.buffer.clone())`、`entry.fluid_buffer.clone()`、`Box::new(entry.light_buffer.clone())`。
  * 每個區塊緩衝區為 32KB，27 個鄰居每次烘焙即產生高達 2.16 MB ~ 2.5 MB 的堆疊深層複製與分配開銷。在地圖加載或玩家連續破壞方塊時，每秒產生數十至上百 MB 的內存垃圾 (GC-free allocator churn)，造成幀率微幅抖動。
* **歷史過時代碼殘留**：
  * 存檔與舊版本兼容層殘留了早已不再使用的 `get_block_global_mut`、`Chunk::get_block`、`Chunk::is_pure_air` 等歷史遺留函數。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **工業級 Amanatides & Woo (1987) 3D 快速體素遍歷 (Fast Voxel Traversal / 3D DDA) (`src/utils/math.rs`)**：
  * 嚴格實作基於整數邊界求交的 3D DDA 演算法，以極低開銷按軸向跳轉體素單元，徹底消滅固定步長帶來的漏網之魚。
  * 結合 Slab Method (AABB 線段盒求交演算法) 精準處理火把等局部子幾何體 (Sub-block AABB)，光線能準確穿透火把所佔空間的空氣部分擊中後方實體。
  * 演算法直接輸出命中表面法線 `hit.normal` 與精確相鄰放置坐標 `hit.adjacent_pos`，徹底替換 `last_air_pos`，使方塊放置與火把貼牆方向 100% 絕對精準。
  * 全面套用於 `player_interaction`、`draw_target_block_highlight` 與 `update_crosshair`，達成系統間共用單一數學真理。
* **區塊網格記憶體零拷貝提取優化 (`src/world/mod.rs` & `src/render/greedy.rs`)**：
  * 將資料層 `ChunkEntry` 中的 `buffer`、`light_buffer`、`fluid_buffer` 全面升級託管為 `std::sync::Arc` 原子參照計數指針。
  * 網格生成提取鄰居時直接執行 `Arc::clone`，僅需 216 位元組之指針複製，**堆疊記憶體分配徹底歸零 (0 Bytes Heap Allocations)**，徹底根治內存震盪！
  * 寫入與修改方塊/光照/流體時採用 Copy-on-Write (`Arc::make_mut`)，在無背景任務競爭時達到零複製零開銷，在背景執行緒烘焙網格時提供安全不可變快照，完美兼顧線程安全與極致效能。
* **無效過時代碼清理與編譯器零警告保證**：
  * 徹底剔除已無未來發展空間之 `get_block_global_mut`、`Chunk::get_block`、`Chunk::is_pure_air`。
  * 清理各模組中的編譯器警告，維持全專案 `cargo check` 0 警告、0 錯誤的商業級規範。

## 🔧 今日重構與修復：視窗啟動游標剛性居中鎖定、ESC 脫離滑鼠與點擊防誤觸重鎖機制

### 1. 缺陷深度診斷 (Root Cause Analysis)
* **啟動後游標卡在遊戲視窗外或未居中**：
  * 在 Windows 平台啟動遊戲時，若滑鼠原本停在終端機或編輯器中，舊代碼未主動將游標定位至視窗中心，`CursorGrabMode::Locked` 會將游標強制錨定在視窗客戶區外的桌面座標，造成玩家必須按 Windows 鍵脫離後重新點擊視窗才能恢復操控。
* **按 ESC 鍵脫離滑鼠功能失效**：
  * `src/ui/inventory.rs` 中的 `toggle_inventory_screen` 判定邏輯存在嚴重漏洞：當背包處於關閉狀態時，按下 ESC 鍵依然會進入其 `else` 分支，無條件執行 `window.cursor.grab_mode = CursorGrabMode::Locked`，覆蓋並摧毀了 `toggle_grab_cursor` 原有的 ESC 游標釋放邏輯。
* **重獲焦點點擊誤觸方塊破壞/放置**：
  * 當游標解鎖後，玩家點擊視窗試圖重新鎖定時，該單次點擊事件同時會傳播給 `player_interaction`，造成玩家剛點進視窗就誤敲方塊或誤放方塊。

---

### 2. 工業級架構重構 (Production-Grade Architecture)
* **多層防禦游標剛性置中鎖定 (`src/main.rs` & `src/player/mod.rs`)**：
  * 在 `WindowPlugin` 的 PrimaryWindow 描述器中直接預設 `Cursor { grab_mode: Locked, visible: false }`，保證 Winit 建立視窗瞬間即向 OS 請求鎖定游標。
  * 在 `setup_player` 與 `toggle_grab_cursor` 啟動階段，偵測視窗寬高尺寸就緒 (`window.width() > 0.0`) 時，立即透過 `window.set_cursor_position(Some(center))` 精確將滑鼠置於視窗正中央 `(width/2, height/2)`，徹底消滅游標漂移至視窗外被定住的問題。
* **ESC 游標釋放與背包狀態機徹底解耦 (`src/ui/inventory.rs`)**：
  * 在 `toggle_inventory_screen` 中加入 `if !press_e && (!press_esc || !state.is_open) { return; }` 防線。若背包未開啟，ESC 鍵直接略過背包系統，全權交由 `toggle_grab_cursor` 將游標釋放 (`CursorGrabMode::None`, `visible = true`)。
* **點擊重鎖防誤觸安全閘門 (`CursorJustLocked`)**：
  * 引入 `CursorJustLocked` 資源，當游標處於解鎖狀態時，玩家點擊左鍵或右鍵僅會觸發「游標置中並鎖定」，並標記 `CursorJustLocked`；
  * `player_interaction` 於同影格檢測到此旗標時直接早期返回，杜絕重獲焦點時的意外方塊破壞或放置。
  * 當游標處於脫離狀態時，`draw_target_block_highlight` 與 `player_input_capture` 自動休眠，確保畫面潔淨與輸入隔離。

### 3. 單元測試與自動化校驗 (Unit Testing & Quality Assurance)
* 新增單元測試 `test_cursor_release_on_escape_and_relock_on_click`：
  * 驗證初生影格自動鎖定並置中 `(640, 360)`；
  * 驗證按下 ESC 成功釋放游標 (`grab_mode == None`, `visible == true`)，且不被背包系統覆蓋；
  * 驗證點擊左鍵重新鎖定並精確置中，且當幀標記 `cursor_just_locked`；
  * 驗證次幀 `cursor_just_locked` 自動復位恢復正常遊玩。
